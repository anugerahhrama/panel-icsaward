## Check `resources/js/components/ui/` for an already-installed shadcn primitive before building interactive UI from scratch

Before reaching for a plain `useState` toggle or adding a new shadcn/Radix package, check whether the primitive is already scaffolded but unused — `package.json` may already list the underlying `@radix-ui/react-*` package, and `resources/js/components/ui/` may already wrap it (e.g. `collapsible.tsx` wrapping `@radix-ui/react-collapsible`) from an earlier `npx shadcn add` that nothing on the landing page ended up using yet. Found during the FAQ section session: `Collapsible`/`CollapsibleTrigger`/`CollapsibleContent` were already present and unused, so the FAQ accordion (`resources/js/components/faq/faq-item.tsx`) reused them directly instead of hand-rolling expand/collapse state or adding a dependency — keeps `.ai/rules/index.md`'s "don't change dependencies without approval" constraint a non-issue. Check `resources/js/components/ui/` and `package.json`'s `@radix-ui/*` entries first for any future interactive pattern (tabs, tooltips, popovers, etc.).

## Admin UX conventions: loading, feedback, confirm dialogs, modal-vs-page threshold

Established during the Site Settings admin page session (first Milestone 2 page) — every later admin CRUD session should follow the same conventions rather than re-deriving them:

- **Loading state**: dua jenis, jangan ditukar. (1) Tombol yang sedang memproses (submit/simpan/hapus) tetap pakai `Spinner` (`components/ui/spinner.tsx`) di dalam `Button` + `disabled={processing}` — lihat `components/admin/save-button.tsx`. (2) Loading/render halaman atau konten (teks, tabel, kartu, list, deferred props) pakai `Skeleton` (`components/ui/skeleton.tsx`) sebagai placeholder pulsing, bukan spinner. (Diperjelas 2026-09-19.)
- **Success/error/warning feedback**: use `sonner`'s `toast.success()`/`toast.error()`/`toast.warning()` (already installed and mounted globally via `<Toaster />` in `app.tsx`) on every create/update/delete outcome — `toast.error()` with the actual backend error message on failure, `toast.success()` on success. Field-level validation errors still go through the existing `InputError` component, not a toast.
- **Confirm dialogs for delete/logout**: reuse the existing `Dialog` primitive (`components/ui/dialog.tsx`), not a new `AlertDialog`/`@radix-ui/react-alert-dialog` dependency — the codebase already has this exact pattern in `resources/js/components/delete-user.tsx`, extended to logout in `resources/js/components/user-menu-content.tsx` (Site Settings session). Intercept the trigger's `onSelect`/`onClick` to open local dialog state instead of acting immediately.
- **Sheet vs. own page for create/edit forms**: form dengan **kurang dari 8 field** (1–7) dibuat dengan `Sheet` (`components/ui/sheet.tsx`, side panel), bukan `Dialog`; form dengan **8+ field** dapat halaman create/edit sendiri. Berlaku untuk semua sesi CRUD Milestone 2 ke depan — mis. Admin User Management (tambah user) pakai `Sheet`. Reference: Judges (7 field) di `resources/js/pages/admin/judges/index.tsx` + `components/admin/judges/judge-form.tsx` (`onSaved` menutup Sheet). Site Settings tetap dikecualikan. `Dialog` hanya untuk confirm delete/logout, plus satu pengecualian: preview dokumen (bukan form) memakai `Dialog` lebar (`sm:max-w-5xl h-[85vh]`) karena Sheet terlalu sempit untuk slide. Reference: `components/admin/participants/file-preview-dialog.tsx` (dipakai juga dari dalam Verification sheet). (Ambang diubah dari 5 ke 8 pada 2026-09-19.)
- **File upload**: setiap field upload file wajib pakai komponen `Attachment` (`components/ui/attachment.tsx`, shadcn registry `@shadcn/attachment`), bukan `<Input type="file">` polos. Reference: `components/admin/logo-upload-field.tsx` (input file `sr-only` + `AttachmentTrigger` yang klik input, preview via `AttachmentMedia variant="image"`, `AttachmentAction` untuk hapus pilihan, `state` idle/done/error). Reuse/extend komponen itu untuk field upload baru (foto juri, logo, gambar, media kit) daripada bikin ulang. Jebakan CLI: `shadcn add` generate `import { cn } from "cn"` (ganti ke `@/lib/utils`), dan `Attachment` butuh `Button` size `icon-xs` (sudah ditambah ke `button.tsx`); jawab `n` saat CLI tanya overwrite `button.tsx`.
- **List loading**: reuse `components/ui/skeleton.tsx` for a data table's loading state, matching the pulsing-skeleton pattern already used for Inertia deferred props elsewhere in the app.
- **Content area padding**: every admin page's root content element gets `flex h-full flex-1 flex-col gap-4 overflow-x-auto rounded-xl p-4` — same classes `dashboard.tsx` uses on its outer `<div>`. `AppContent`/`SidebarInset` (the shared admin layout) applies no padding of its own, so each page is responsible for it; without this class list a page sits flush against the sidebar/header with no breathing room (found on the original single-page Site Settings, corrected after it shipped with no padding). Apply it to the outermost element every future admin page returns (a `<form>`, a `<div>`, whatever that root happens to be) — don't reinvent different padding per page.
- **Split a growing settings/CRUD page into grouped sub-pages behind a collapsible sidebar sub-menu once it gets too long**: Site Settings started as one page with 12 accordion sections; the user asked for it to be split into 3 topical sub-pages (`resources/js/pages/admin/settings/{landing,identity,system}.tsx`, one `useForm`/route/controller/`FormRequest` each — not one shared endpoint fed by three frontends) once it grew unwieldy. `NavItem` (`types/navigation.ts`) now supports an optional `items?: NavItem[]` for nesting, and `NavMain` (`components/nav-main.tsx`) renders a `Collapsible` + `SidebarMenuSub`/`SidebarMenuSubItem`/`SidebarMenuSubButton` (shadcn sidebar primitives, previously unused in this codebase) whenever a top-level `NavItem` has `items`, auto-expanded via `isCurrentOrParentUrl`. Reuse this same pattern (separate route/controller/page per sub-group, `items` on the sidebar entry) for any future admin section that grows past a single comfortable page — don't keep stacking more accordions onto one page or one endpoint.

## `LogoUploadField` handles non-image uploads via `accept`/`hint`

For a non-image upload (e.g. media kit PDF/ZIP), pass `accept` and `hint` to `components/admin/logo-upload-field.tsx` instead of building a new component. When `accept` doesn't start with `image`, the preview falls back to the file icon (no `<img>` of a PDF). Defaults keep the image behaviour (Media CRUD session, 2026-09-20).

## Supergraphic lewat komponen `<Supergraphic>`, layer dekoratif pakai `isolate` + `-z-10`

Aset brand supergraphic dipasang lewat `components/supergraphic/supergraphic.tsx` (`variant="01"`–`"08"`), bukan `<img>`/import manual. Parent diberi `relative isolate overflow-hidden`, layer `absolute -z-10` — negative z-index di dalam stacking context `isolate` tergambar di atas background parent tapi di bawah semua child, jadi child tidak perlu `relative` satu-satu. Di latar terang (`bg-surface`) pakai opacity rendah + `[mask-image:radial-gradient(circle_at_top_right,black,transparent_70%)]` agar tepi artboard tidak terlihat; hindari varian 01 (bola 3D) sebagai aksen pojok — tepinya terpotong rata dan terlihat seperti stiker (feedback user, 2026-09-26). Di latar gelap pakai `object-cover` full-bleed + overlay `bg-deep/70` bila ada teks di atasnya.

## SVG ekspor Illustrator: buang `<i:aipgf>` sebelum masuk repo

SVG dari Adobe Illustrator membawa data edit `<i:aipgf>` (base64 zstd) yang ±98% ukuran file (supergraphic: ~1 MB → ~7 KB). Strip `<i:aipgf>…</i:aipgf>`, `<i:aipgfRef/>`, komentar Generator, dan `xmlns:i` (perl one-off) sebelum menaruh SVG di `resources/images/`. Jangan pakai SVGO (tidak terpasang; berisiko ke `mix-blend-mode`/`clipPath`). SVG yang isinya PNG ter-embed → ekstrak PNG, crop ke artboard, konversi `cwebp` (sudah terpasang via Homebrew). Quick Look/ImageMagick tidak merender viewBox-clip & gradient dengan benar — cek hasil di Chrome.

## Background Key Visual lewat `<KeyVisual composition="…">`, bukan supergraphic (2026-09-27)

`components/key-visual/key-visual.tsx` = layer dekoratif `absolute inset-0 -z-10` (parent wajib `relative isolate`): utility `bg-kv-*` + cincin konsentris SVG inline (`preserveAspectRatio="xMidYMid slice"`, `vectorEffect="non-scaling-stroke"`), dua `<svg>` landscape/portrait di-switch dengan `hidden sm:block`/`sm:hidden` (tanpa JS, aman SSR), `scrim` opsional (`left-bottom`/`center`). Komposisi yang dibawa: `corners` (panel brand auth) dan `stage` (banner Overview admin/juri); `spotlight` dibuang bersama utility-nya. Tambah komposisi baru di map `compositions`, jangan bikin komponen background kedua. `Supergraphic` untuk aksen di latar terang.
